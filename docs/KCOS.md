# KCOS — an operating system written in KingCobra

KCOS is a small x86-64 operating system. **The kernel is KingCobra source compiled by `kcc`** (`kcc --target kcos`, see
[KCC.md](KCC.md#freestanding-target-kcos)); only the BIOS boot stage — real mode and 32-bit protected mode, which `kcc` cannot emit —
is assembly (`kcos/boot/boot.asm`, about 250 lines, shipped pre-assembled as `boot/boot.bin`, so *building* KCOS needs no assembler).

**Status: v0.1, a working kernel with a shell — not a general-purpose OS.** Verified by booting in QEMU (`make -C kcos test`: 19 checks, two boots of one disk, plus the
VGA output and the PS/2 keyboard by hand). It has **not** been run on real hardware, VirtualBox or VMware.

## Build and run

```bash
make                  # once: the KingCobra interpreter (repository root)
make -C kcos          # kcos/build/kernel.bin  and the bootable image  kcos/build/kcos.img
make -C kcos run      # boot it in QEMU            (or: qemu-system-x86_64 -drive format=raw,file=kcos/build/kcos.img -m 128)
make -C kcos run-serial   # headless: the shell is on your terminal over COM1
make -C kcos test     # boot headless, drive the shell, check the output
```
The image is a raw disk image. Write it to a USB stick with `dd if=kcos.img of=/dev/sdX` to try BIOS (CSM/legacy) hardware at your own risk;
for VirtualBox convert it first (`VBoxManage convertfromraw kcos.img kcos.vdi --format VDI`). BIOS only — there is no UEFI boot.

## What is in it

| Part | File | |
|---|---|---|
| Boot stage 1 + 2 | `boot/boot.asm` | MBR loads stage 2; A20, VGA text mode, E820 memory map, loads the kernel (INT 13h LBA), builds page tables (4 GiB identity map in 2 MiB pages, devices above 3 GiB uncached), enables SSE, enters long mode |
| Entry + interrupt stubs | generated by `kcc` | `kmain` call, 256 vector stubs, register save, `kc_interrupt` |
| GDT, TSS, IDT, PIC, PIT, PS/2 keyboard, RTC, speaker, exceptions | `kernel/hw.kc` | exceptions print a register dump and halt; double fault runs on its own IST stack |
| Console | `kernel/console.kc` | 80×25 VGA text with colour, hardware cursor, scrolling; everything is mirrored to COM1 (115200 8N1), which is also an input source |
| Threads | `kernel/sched.kc` | preemptive round-robin kernel threads (20 ms slices, up to 8): `spawn(fnaddr(f), arg)`; built on `kc_switch`, `fnaddr`, `callp` and the atomics |
| ATA disk + persistent KCFS | `kernel/disk.kc` | ATA PIO driver (primary master, LBA28, `rep insw/outsw`); `sync` saves the whole filesystem at LBA 1024 (256 KiB reserved), the next boot restores it |
| Physical memory + heap | `kernel/mm.kc` | bitmap frame allocator over the E820 map; first-fit heap with splitting and coalescing (`kmalloc`, `kzalloc`, `kfree`) |
| KCFS | `kernel/fs.kc` | in-memory hierarchical filesystem on the heap: 128 nodes, 27-character names, files grow on demand |
| Shell | `kernel/shell.kc` | line editor, history (Up/Down), Ctrl+C / Ctrl+L / Ctrl+U |
| Image builder | `tools/mkimage.kc` | `boot.bin` + `kernel.bin` → `kcos.img` (written in KingCobra, run by the interpreter) |

### Shell commands
`ls cd pwd cat mkdir touch rm echo (> and >>) stat fsinfo sync fsreset disk` · `threads tasks` · `mem memmap heap cpuinfo uptime date ver clear history` ·
`calc hexdump sleep beep color cobra` · `reboot halt poweroff` · `crash` (deliberate divide-by-zero, shows the panic screen).
The filesystem lives in RAM and starts out with `/etc`, `/home`, `/docs`, `/tmp`; `sync` writes it to the boot disk (and it is restored at the next boot), until then it is gone after a reboot. `threads` runs three preemptively scheduled workers doing 300,000 atomic increments each and checks the total.

## Memory map (physical)

| Range | Use |
|---|---|
| `0x00500` | boot info: `'KCOS'`, E820 entry count, boot drive, kernel sectors; E820 entries (24 bytes each) from `0x510` |
| `0x01000–0x06FFF` | boot page tables (PML4, PDPT, 4 PDs) |
| `0x07C00–0x083FF` | MBR and stage 2 (the boot GDT is discarded by `gdt_init`) |
| `0x10000–0x6FFFF` | kernel image (entry stub, interrupt stubs, `.text` … `.bss`); at most 384 KiB |
| `0x70000–0x7FFFF` | kernel stack (grows down from `0x80000`) |
| `0xB8000` | VGA text buffer |
| disk LBA 1024–1535 | persistent KCFS store (header sector + up to 256 KiB); keep the image at least 1 MiB (the builder pads to that) |
| `0x100000–0x11FFFF` | frame-allocator bitmap |
| `0x400000 …` | kernel heap (up to 32 MiB) |

## Writing kernel code in KingCobra

The kernel uses the native subset of KingCobra that `kcc` compiles (see [KCC.md](KCC.md)): `int`/`u8…u64`/pointers/structs/arrays, `if/while/for`,
functions, globals. There are no strings as values (a literal is a `*u8`), no function pointers, no `switch`, no `print` — the kernel has its own
`con_puts`, `con_putdec`, … Port I/O, `cli`/`hlt`, `lidt` and friends are compiler intrinsics. Two things worth knowing:

- `var a: *u8[16]` is a **pointer to an array** (8 bytes), not an array of pointers; use `int[16]` and cast, as `shell.kc` does for `argv`.
- Integer `/` is truncating `idiv` and **traps on zero** (that is what the `crash` command shows).

## Limits and what is not there yet

- Single CPU, legacy PIC (no APIC / SMP), BIOS boot only, text mode only (no framebuffer), PS/2 keyboard (USB keyboards work where the firmware or VM emulates PS/2, as QEMU does).
- No user mode, no system calls, no program loader — the kernel threads and the shell all run in ring 0. The scheduler is round-robin only (no priorities, sleeping or locks beyond the atomics); the heap is not thread-safe, so only the boot thread allocates.
- The disk driver is PIO-only and handles the first IDE master (no AHCI/NVMe/USB, no interrupts, no partitions). The persistent store is a flat dump of KCFS, not a real on-disk filesystem format; a crash during `sync` can leave the previous copy invalid.
- No paging management after boot (the identity map stays; no page faults are handled except by the panic screen); no ACPI use beyond `poweroff` writing QEMU/Bochs/VirtualBox shutdown ports.
- Kernel image limit 384 KiB with the current boot layout.

A sensible order for what comes next: ring 3 + syscalls (user-accessible page mappings, TSS `rsp0`, `int 0x80` or `syscall` via `wrmsr`), a locked heap and sleep/wakeup,
a real on-disk filesystem (FAT or a journaled KCFS), AHCI, then a `.kc` program loader.
